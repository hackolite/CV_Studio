# Fix Summary: Tracking Visualization Not Appearing

## Problem Statement

**Original Issue (French)**: "le tracking ne marche pas, il ne se dessinne pas, pk ?"  
**Translation**: "tracking doesn't work, it doesn't draw, why?"

## Root Cause Analysis

The tracking labels (TID and CID) were **invisible** when objects were detected near the top of the image. 

### Technical Details

When drawing tracking labels, the code calculated text positions as:
- TID position: `(x1, y1 - vertical_offset_1)` where `vertical_offset_1 = 36` pixels
- CID position: `(x1, y1 - vertical_offset_2)` where `vertical_offset_2 = 12` pixels

**Problem**: If an object's top edge `y1` was less than the offset (e.g., `y1 = 10`, offset = 36), the text Y coordinate became **negative** (e.g., `10 - 36 = -26`).

**OpenCV Behavior**: `cv2.putText()` does not draw text when Y coordinate is negative. The text is simply not rendered, making tracking labels completely invisible.

### Example Scenario

```python
# Object detected at top of image
bbox = [100, 5, 200, 100]  # y1 = 5
vertical_offset_1 = 36

# Text position calculation
text_y = 5 - 36 = -31  # NEGATIVE!

# Result: cv2.putText() draws nothing
```

## Solution

Clamp text positions to ensure they always stay within visible image bounds.

### Implementation

Added a minimum text Y position and clamped all text coordinates:

```python
# Calculate minimum safe Y position
min_text_y = max(vertical_offset_1 + 5, 15)

# Clamp TID position
tid_y = max(y1 - vertical_offset_1, min_text_y)

# Clamp CID position  
cid_y = max(y1 - vertical_offset_2, min_text_y)
```

This ensures:
- Text is never drawn at negative coordinates
- Text remains visible even for objects at y=0
- Text has minimum 5-pixel padding from top edge
